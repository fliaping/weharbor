# 首次使用：从登录微信到读取第一条消息

本页适用于 WeHarbor 0.1.0 的 Linux 组合：WeChat 4.1.13.23、WeFlow 6.3.2。
界面名称和获取密钥的顺序按此版本说明；其他版本可能不同。
先按 [README](../README.md#本地构建与启动) 完成构建和启动，再从这里继续。

[English](first-run.en.md)

WeFlow 使用本机微信账号的数据库密钥读取该账号的本地聊天数据库。
手机扫码登录、数据库解密、API 鉴权是三个独立步骤；安装 skill 不会替你完成前两步。

| 阶段 | 完成标志 |
| --- | --- |
| 打开桌面 | 能在浏览器中看到微信和 WeFlow 窗口 |
| 登录微信 | 微信会话列表出现，本地账号数据已生成 |
| 获取数据库密钥 | WeFlow 显示获取成功，并选中了对应账号 |
| 连接数据库 | WeFlow 完成向导，能打开一个会话并看到消息 |
| 开启 API | health 正常，带 Token 能查询会话和消息 |
| 接入 AI | AI 所在环境能访问 API，并成功读取少量消息 |

## 1. 打开浏览器桌面

在 Docker 主机上打开 `https://localhost:3001`，使用本地 `.env` 中的
`CUSTOM_USER` 和 `PASSWORD` 登录。若修改了 `HTTPS_PORT`，使用实际端口。
首次使用自签名证书时，核对访问地址后按浏览器提示继续。

默认桌面端口只绑定宿主机回环地址。在另一台电脑访问时，可以使用 SSH 隧道：

~~~bash
ssh -N -L 3001:127.0.0.1:3001 user@your-docker-host
~~~

然后在这台电脑打开同一个 `https://localhost:3001`。正式域名和反向代理部署
见 [README](../README.md#本地构建与启动)。

微信和 WeFlow 会自动启动。使用桌面上的悬浮切换器在两者间切换。
此时容器显示 healthy 仅代表程序和桌面服务正常，并不代表已经能读取聊天记录。

## 2. 首次登录微信，让本地数据库生成

1. 切换到微信，用手机扫码，并在手机上确认登录。
2. 等待会话列表和近期消息加载，打开一个熟悉的会话确认有文字消息。
3. 保留这个账号的数据，继续 WeFlow 配置。

WeFlow 能读取的是这个 Linux 微信实例已经保存在本地的数据。手机上有的
全部历史记录不会因此自动出现在容器里；某个会话缺少历史时，先检查微信
客户端本身是否已有这些消息，再检查 WeFlow。

## 3. 在 WeFlow 选择数据库目录

首次启动进入配置向导，依次是“欢迎”“数据库目录”“缓存目录”
“解密密钥”“图片密钥”“安全防护”。

在“数据库目录”点击“自动检测”。本项目的通常路径是：

~~~text
/config/Documents/xwechat_files
~~~

这是指向 `/config/xwechat_files` 的兼容链接。自动检测失败时，点击“浏览”
选择实际的 `xwechat_files` 根目录；也可在微信的存储位置设置中核对。
不要填写宿主机上的 `./data` 路径，WeFlow 看到的是容器内路径。

根目录下应有账号子目录，账号子目录内有 `db_storage`。向导能继续到下一步
说明已识别可用账号数据；如果提示缺少 `db_storage`，先返回微信完成登录，
并确认没有选错目录。

“缓存目录”可以留空使用默认值。自定义时也应放在 `/config` 下，
这样缓存能随数据卷保留。

## 4. 获取数据库密钥：先准备，再确认登录

**Linux 首次自动获取密钥通常需要再登录一次。不要在 WeFlow 准备完成前确认登录。**

WeFlow 6.3.2 的 Linux 流程会结束当前微信进程、重新启动微信，
再通过自带 helper 等待登录过程中出现的数据库密钥。操作顺序如下：

1. 在微信中关闭“自动登录”，然后退出登录，保持在未登录状态。
   若部署配置中 `ENABLE_WECHAT_AUTO_LOGIN=true`，首次获取前建议临时改为
   `false` 并执行 `docker compose up -d`。部署脚本的自动登录和微信自身
   的自动登录选项分别控制，均应避免提前登录。
2. 回到 WeFlow 的“解密密钥”，点击“自动获取密钥”，阅读确认框后开始。
   微信窗口关闭并重新出现是此版本的正常准备过程。
3. 等待 WeFlow 提示准备就绪、允许登录，或显示
   “授权通过后请在手机上确认登录微信，正在等待密钥回调”。
   如果出现管理员授权提示，先完成授权。WeHarbor 已集成
   `SYS_PTRACE`、polkit 服务和容器内授权规则。
4. 切换到微信，再扫码或点击登录，并在手机上确认。
5. 回到 WeFlow，等待“密钥获取成功”。密钥字段应填写完成，
   并确认所选微信账号与刚登录的账号一致；有多个账号时尤其需要核对。

如果提示“未能自动启动微信”，从桌面打开微信，看到登录窗口后点击
WeFlow 的“我已看到登录窗口，继续”，仍然等待准备完成再确认登录。
如果超时或提前登录了，退出微信登录，重新执行这一步。

数据库密钥是账号凭据，留在 WeFlow 的本地配置中即可。无需抄到终端、
发送给 AI，或提交到 GitHub。已有该账号有效密钥时，向导也支持手动填写。

## 5. 图片密钥与完成配置

数据库密钥用于聊天数据库；图片 XOR / AES 密钥用于解码图片，二者不同。

进入“图片密钥”时，WeFlow 会尝试从本地缓存自动计算。如果暂时没有图片
缓存，可先在微信中打开几张图片，等待下载后回到 WeFlow 点击“重新计算”。
仍失败时，可以尝试“内存扫描”，微信需要保持运行。

首次向导允许在尚未得到图片密钥时继续配置。先完成文字消息读取即可；
图片不可读时再补充图片密钥，不要因此重新获取已经有效的数据库密钥。

“安全防护”中的应用锁按需配置。它的密码与浏览器桌面密码、API Token 都不同。
点击“完成配置”；此时 WeFlow 会测试并打开数据库。成功后进入首页，
打开一个已有会话，对照微信确认几条文字消息。也可在“设置 → 数据库连接”
中点击“测试连接”复查。

**以能看到自己的消息作为数据库配置成功的标准。**

## 6. 开启并验证 HTTP API

在 WeFlow 的“设置 → API 服务”找到“HTTP API 服务”。如果服务已启动，先关闭开关，
因为运行时监听地址和端口不可编辑。然后设置：

| 设置 | 值 |
| --- | --- |
| 监听地址 | `0.0.0.0`，用于接收 Docker 端口转发和同网络容器请求 |
| 服务端口 | 与 `.env` 的 `WEFLOW_API_PORT` 一致，默认 `5031` |
| Access Token | 点击“随机生成”，将凭据保存在自己的环境或 secret 管理器 |
| HTTP API 服务 | 开启，状态应为“运行中” |
| 主动推送 | 需要实时通知或 SSE 时再开启，并检查会话过滤设置 |

容器内监听 `0.0.0.0` 与宿主机对外公开是两回事：默认 Compose 仍然只
将 API 映射到宿主机 `127.0.0.1`。`.env` 的端口设置不会自动修改 WeFlow
界面中的持久化配置。

在 Docker 主机的 Bash 终端执行下列检查。使用实际端口替换 `5031`。

~~~bash
# 这一步只检查 API 服务是否存活，不检查数据库和鉴权。
curl --fail http://127.0.0.1:5031/health

# 在本地输入 Token，输入内容不会回显或写入该命令的历史记录。
read -r -s -p 'WeFlow API Token: ' WEFLOW_API_TOKEN
printf '\n'
export WEFLOW_API_TOKEN

curl --fail --get \
  -H "Authorization: Bearer $WEFLOW_API_TOKEN" \
  --data-urlencode 'limit=5' \
  http://127.0.0.1:5031/api/v1/sessions
~~~

从 `sessions` 数组中选一个会话的 `username`，它是消息查询的 `talker`，
不是群昵称或显示名。用返回的真实值替换下面的占位符：

~~~bash
curl --fail --get \
  -H "Authorization: Bearer $WEFLOW_API_TOKEN" \
  --data-urlencode 'talker=REPLACE_WITH_SESSION_USERNAME' \
  --data-urlencode 'limit=5' \
  http://127.0.0.1:5031/api/v1/messages
~~~

会话和消息接口应返回 `success: true`，并能查到刚在 WeFlow 中确认的消息。
只有 `/health` 返回 `status: ok` 还不足以证明可以读取聊天记录。

## 7. 安装 skill，让 AI 读取少量消息

把 [skill 安装页 URL](https://raw.githubusercontent.com/fliaping/weharbor/main/docs/install-skill.md)
交给支持技能和命令执行的 AI 工具，或者按 [安装说明](install-skill.md) 执行安装命令。

在 **AI 执行环境** 中配置 `WEFLOW_API_BASE` 和 `WEFLOW_API_TOKEN`，
也可用 `WEFLOW_API_TOKEN_FILE` 指向本地凭据文件。默认地址
`http://127.0.0.1:5031` 只有在 AI 与 API 位于同一网络命名空间，或已建好
隧道时才适用；同一 Docker 网络的其他容器用 `http://weharbor:5031`。

先让 AI 检查 health，查询少量会话，再读取指定会话的少量消息。
可以说：“找到我指定的项目群，读取最近几条文字消息，确认接入成功。”
确认正确后再做按时间查询、群聊摘要或限时 SSE 订阅。
真实数据库密钥与 Token 不需要发到 AI 聊天窗口。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 容器 healthy，但 WeFlow 没有消息 | 是否完成账号、数据库密钥与连接测试；health 不检查账号数据是否可读 |
| 找不到账号或缺少 `db_storage` | 微信是否首次登录完成；是否选了容器内正确的根目录 |
| 自动获取时微信突然关闭 | 6.3.2 Linux 的准备过程会重启微信；等准备完成再登录 |
| 获取密钥超时 | 是否提前确认登录或仍开启自动登录；退出登录后按第 4 步重试 |
| 管理员授权 / Hook 失败 | 是否用仓库 Compose 保留了 `SYS_PTRACE`；polkit 是否运行；记录已脱敏错误后排查 |
| 密钥存在但连接失败 | 账号、数据库目录和密钥是否对应；换账号后不能沿用旧账号密钥 |
| 文字正常，图片打不开 | 先下载几张图片，再获取图片密钥；检查本地媒体是否存在 |
| 历史记录不完整 | 对照 Linux 微信里实际可见的历史；WeFlow 不会自动拉取手机全部记录 |
| API 连接失败或拒绝连接 | API 是否“运行中”；容器内是否监听 `0.0.0.0`；端口是否与 Compose 一致 |
| API 返回 401 | 使用 API Token，而不是网页登录密码或数据库密钥；核对 Token 是否更新 |
| SSE 没事件 | 主动推送与过滤规则；微信是否在线；观察期间是否真的有新消息 |
| skill 已安装却无法读取 | AI 的网络与凭据是否配置；远程环境的 `localhost` 不指向用户的 Docker 主机 |

重启后使用同一个 `/config` 卷，账号配置和数据会保留，无需每次重新获取密钥。
微信可能仍需要重新确认登录；账号变更或密钥失效时再按对应步骤处理。
升级前备份完整数据，见 [维护与迁移](operations.md)。提交 issue 时仅提供版本、
失败阶段和脱敏错误，不附完整 `weflow.log`、微信数据库、账号配置或密钥截图。
